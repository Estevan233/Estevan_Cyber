# 幕布式首页与每日精选封面设计

日期：2026-08-13
状态：已确认，待实施
目标分支：`codex/hybrid-studio-homepage`
关联 PR：`Estevan233/Estevan_Cyber#4`

## 1. 目标

将当前首页从“首屏同时暴露内容”的传统长页面，调整为自然滚动的幕布式体验：首屏只呈现每日精选图像、站点身份和探索入口；用户滚动或点击下拉按钮后，浅色内容幕布覆盖首屏，并逐层展示进度、标签、歌单、文章和其他站点内容。

首页仍应保持快速、可访问、可维护。不得使用强制滚动吸附、远程随机图片接口或重型视差库。

## 2. 已确认决策

- 采用自然滚动幕布，不使用 `scroll-snap-type: mandatory`。
- 首屏信息密度采用 A：站名、一句短文案、图片主题说明和下拉按钮。
- 封面图库本地托管，首批 6 张原创图像。
- 图像风格涵盖风景、电影感场景、匿名人物和萌宠，不直接使用电影剧照、角色形象、明星肖像或来源不清的网络图片。
- 图像按访问者本地日期每日稳定轮换；同一天刷新保持同一张，跨日自动切换。
- 时间进度、标签云和歌单移动到内容幕布顶部。
- 暗色模式继续保留。

## 3. 页面结构

### 3.1 首屏幕布背景

Hero 高度为可用视口高度，使用 `100svh` 并为旧浏览器提供 `100vh` 回退。桌面端考虑站点顶部导航高度，移动端保证下拉按钮不会被浏览器工具栏遮挡。

首屏只显示：

1. `Estevan Cyber`
2. 短文案：`技术、生活与仍在进行的实验。`
3. 当日图片的主题或场景说明
4. 指向 `#home-content` 的下拉按钮

不在首屏展示文章、项目、问答按钮、侧栏卡片或大段介绍。导航栏保持可用，但在 Hero 顶部呈半透明外观；进入内容区后恢复实体背景。

### 3.2 内容幕布

内容容器位于 Hero 之后，具有独立浅色背景和高于 Hero 的层级。向下滚动时它自然覆盖背景图，形成“拉开幕布”而不是人为拦截滚轮。

内容顺序：

1. 探索概览：年度进度、标签云、歌单
2. 最新文章与近期方向
3. 站点设施

桌面端探索概览使用三栏布局。时间进度占较窄列，标签云占较宽列，歌单使用可展开列。移动端依次堆叠为时间进度、标签云、歌单。

当前“今日 / 本周 / 本月 / 今年”四项进度缩减为一个突出显示的“年度进度”，以符合用户此前选择并减少噪声。

最新文章仍为主内容。近期方向移动到文章区域右侧，不再让四个侧栏模块从上到下把页面拖成长条。

## 4. 每日封面图库

新增 `data/hero-images.yaml`，每项包含：

```yaml
- id: dawn-coast
  src: images/home/curtain/dawn-coast.png
  title: 海岸晨光
  category: 风景
  alt: 清晨海岸上被金色阳光照亮的岩石和海浪
  position: center
```

首批图库构成：

- 风景 2 张
- 电影感场景 2 张
- 匿名人物 1 张
- 萌宠 1 张

所有图片均为原创生成图，并在仓库中保留统一尺寸和命名。每张图由 Hugo 生成桌面与移动端 WebP 版本；`position` 用于保护人物、动物或主体在不同裁切比例下不被切掉。

## 5. 轮换与加载

新增独立的 `home-curtain.js`：

1. 将本地日期格式化为 `YYYY-MM-DD`。
2. 对日期字符串计算稳定整数哈希。
3. 使用 `hash % imageCount` 得到当日图片索引。
4. 把对应图片 URL、`srcset`、`alt`、标题和分类写入唯一的 Hero `<picture>`。
5. 图片加载完成后添加就绪类，仅执行短暂透明度过渡。

非当日图片只作为数据存在，不生成可下载的 `<img src>`，避免浏览器同时请求 6 张壁纸。首屏图片使用明确尺寸、响应式 `srcset`、`fetchpriority="high"` 和 `decoding="async"`。脚本失败时回退到图库第一张，并保持文本可见。

轮换逻辑必须是纯函数并导出给 Node 测试，包含：日期键、稳定哈希、索引选择和空图库回退。

## 6. 交互与可访问性

- 下拉按钮是有可访问名称的链接，不使用仅靠手势触发的隐藏交互。
- 点击后滚动到 `#home-content`，并为锚点设置与固定导航匹配的 `scroll-margin-top`。
- 页面不锁定滚动，不劫持滚轮，不强制分页吸附。
- 文案和按钮在所有封面上保持 WCAG 可读对比度，通过局部暗色遮罩实现，不使用覆盖整图的厚重渐变。
- `prefers-reduced-motion: reduce` 时关闭平滑滚动、位移和淡入动画。
- 图片说明保持简短；`alt` 描述画面，不重复站名或分类标签。
- 无 JavaScript 时展示第一张图，页面内容和下拉锚点仍可访问。

## 7. 响应式排版

- `>= 1024px`：全屏 Hero；探索概览三栏；文章与近期方向为 2:1。
- `720px–1023px`：探索概览两栏，歌单横跨整行；文章与方向上下排列。
- `< 720px`：Hero 文案靠左下；下拉按钮保持 44px 触控区域；探索概览单列；标签自动换行；歌单默认收起。

内容幕布不使用夸张圆角，不模拟悬浮卡片堆叠。模块之间依赖留白、分隔线和字体层级建立秩序。

## 9. 验收标准

- 首屏在桌面和手机上均只显示精选图片、站名、短文案、图片说明和下拉按钮。
- 同一天重复加载选择同一张封面，修改测试日期后可轮换到其他图片。
- 首屏网络请求只包含一张主封面的实际图像资源。
- 点击下拉按钮或自然滚动都能进入内容区，无滚动锁定或吸附。
- 年度进度、标签云、歌单位于内容区第一组模块。
- 默认浅色和手动暗色模式均清晰可读。
- `prefers-reduced-motion` 下没有滚动或揭幕动画。
- 390×844、768×1024 和 1440×900 无横向溢出、遮挡或文字裁切。
- 播放器不自动播放，切歌和错误状态继续工作。
- Node 测试、Hugo 生产构建、`git diff --check` 和敏感信息扫描全部通过。
- 浏览器控制台无新增错误。

## 10. 非目标

- 不接入 Bing、Unsplash 或其他远程随机图片 API。
- 不自动抓取影视剧照、明星图片或社交平台内容。
- 不实现视频背景、自动轮播、滚轮劫持或强制全屏分页。
- 本轮不合并 PR，也不部署线上环境。
